# ADR 0008 — private conversations and explicit work decisions

Date: 2026-11-02. Milestone 07. Production messaging and workflow flags remain OFF.

A conversation belongs to one real job and one invited provider with a published quote or selected booking. Only the actual client and provider are members; server commands assign sender identity, time and an ordered sequence. Strict, bounded same-origin commands verify the current native session and account capabilities again within a transaction. Worker content access also requires current category/coverage/approval and a retained relevant relationship. Blocks and safety reports pause sending. A client retains their own job history. Workers retain their own private case responses even if manual service approval is revoked, provided their account and worker capability remain active. This exception cannot start work or restore messaging.

The browser polls only while visible and online with bounded backoff. Cursor pages use monotonic per-conversation sequence rather than timestamps; late responses are discarded and merged messages are deduplicated and ordered. Sending and uploads have explicit retry with stable actor/idempotency keys. Drafts and file buffers stay in this tab’s memory, not local storage, service worker caches, URLs or notifications. Reloading loses unsent drafts. No optimistic message is presented as saved.

Completion and message photos use a private bucket, actual malware scanning, image decoding and metadata-stripping re-encoding. Context authorization precedes and follows upload. Reservations reconcile interrupted native Storage uploads by hash without overwriting objects. Only the actual author may attach an unused, retained photo to its original conversation, completion or case. Unsent photos can be withdrawn and queued for physical deletion. Random paths omit original filenames.

Photo access uses an application-signed HMAC ticket in a request header, bound to actor, native session, asset and a maximum 60-second lifetime. The server verifies current permission before and after downloading private bytes. Tickets and Storage paths never appear in URLs or cached command results. The browser revokes temporary Blob URLs at expiry/unmount/page exit. Previously viewed or copied information cannot be recalled. User-authored text and image pixels may themselves contain personal information; this is not semantic redaction.

Only the selected worker reports start at or after the agreed appointment start. Progress updates are participant reports, without continuous GPS. Reschedules and scope/price changes remain proposals until the other party explicitly accepts. Acceptance rechecks current version, expiry, eligibility and schedule. Rejection or withdrawal retains the prior agreement, including when intervening progress made acceptance stale. Accepted quote terms and the booking’s original amount remain immutable: current agreed amount is original ZAR cents plus all accepted signed change deltas, bounded at R1 million. M08 must use that effective agreement rather than charging the original amount alone.

Completion appends a numbered immutable submission with scanned evidence or a detailed explanation. Only the client explicitly confirms or requests correction. A correction retains prior evidence and returns to work in progress; a service issue pauses completion and opens support review. Either actual party may raise an issue without an arbitrary waiver deadline. Private case responses/files are support-only; only the submitting participant and authorized support can view them. Shared support notes are clearly distinct. M07 supports intake, evidence and triage, not fault adjudication, case closure, payments, refunds or penalties (later milestones).

The configurable review window defaults to 48 hours. An authenticated operator batch marks overdue pending submissions as requiring support review and writes deduplicated actual in-app notices. It never accepts work, completes a booking, releases funds or waives rights. There is no provisioned public cron. Private file cleanup is another protected bounded operator batch: expired or withdrawn unheld objects are removed and audited, interrupted deletion can reconcile only a verified 404, and case-held evidence is retained. Retention-expired files are unreadable even if held. Approve retention and legal hold operations before hosted activation; M09 must supply case disposition and hold release.

Owner/support evidence access requires native MFA, a current role/session, an explicit recorded reason and a five-minute actor/session-bound grant. Staff cannot audit their own client/provider cases. Audit projections exclude exact locations, worker bases, bank details, contact numbers and verification documents. Every photo request rechecks the grant and role. The retained audit session identifier deliberately has no foreign key to ephemeral Auth sessions: logout must delete the session without deleting or being blocked by its immutable audit history. This is a scoped work evidence audit, not blanket administrator table access or the full M09 moderation console.

The CLI-created migration tightens direct browser SELECT with restrictive RLS on conversations, members, messages, change orders, disputes and safety reports. New evidence, proposals, submissions and grants are private with no browser grants. Legacy conversations without a selected worker remain retained but inaccessible to the new app. Messages and evidence history are immutable; moderation may only tombstone messages. Existing M05 synthetic schedule fixtures now record explicit other-party acceptance as required by the new invariant.

No new package was installed into the manifest or lockfile. Existing pinned SSR/Auth, Node 24, React and Next.js adapters are retained. Reviewed the official Supabase changelog and linked notices: [CBC cipher removal](https://supabase.com/changelog/cbc-tls-ciphers-deprecated), [Postgres 15.19/17.11 breaking changes](https://supabase.com/changelog/postgres-15-19-17-11-breaking-changes), and [locked Realtime schema](https://supabase.com/changelog/realtime-schema-locked-down-against-modification). Keep normal TLS verification. Before upgrading a populated hosted Postgres database, review/reindex affected btree_gist indexes; the M06 schedule exclusion uses this extension. M07 changes no Realtime-owned schema and uses the permitted polling fallback. [Private Storage authorization](https://supabase.com/docs/guides/storage/security/access-control) is checked by the server adapter; native Storage URLs are not public evidence access grants.

Hosted activation requires the approved dedicated Supabase project, reviewed migration/restore, existing M03–06 gates, explicit WORKFLOW_POLICY_APPROVED, retention/scanner operations, signing and scheduler secrets, operator monitoring and support coverage. Disable MESSAGING_ENABLED and WORKFLOW_ENABLED together to withdraw the capability while retaining legitimate records. No hosted migration, provider contact or sensitive flag activation occurs in this milestone. Optional phone/WhatsApp sharing is deliberately omitted: no contact CTA or contact data is exposed.

Stop before Milestone 08.
